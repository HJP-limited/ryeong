# 성능 지표 — 최종 채택 10개와 근거

발표에 쓰는 수치와 그 근거. **검색 / 멀티턴 / 고정셋 / 실기기**는 재는 대상이 다르므로
섞어서 보지 않는다. 같은 내용을 브라우저로 보려면 `docs/성능지표.html`.

계산하는 지표는 더 많지만 헤드라인은 아래 10개다. 나머지는 회귀가 났을 때 원인을
분해하는 진단용이라 올리지 않는다.

## 검색 — 5개

`python scripts/eval_search.py` · 질의 203개(랭킹 183 + 기권 20) · LLM 미사용이라 재현된다.

| 지표 | 값 | 무엇을 재나 | 근거 |
|---|---|---|---|
| R@5 | **0.930** | 화면 5칸 안에 정답이 들어오나 | 앱과 **같은 FTS4 랭커**로 잰다. 분모 `min(정답수,5)`라 상한 1.0 |
| P@R | **0.880** | 쓸데없는 걸 섞지 않나 | 정답이 R개면 상위 R개만 본다. **유형 비교는 이걸로** — P@5는 정답 1~2개 유형에서 상한이 0.2다 |
| MRR | **0.926** | 첫 정답을 얼마나 위에 올리나 | 정답 개수에 안 좌우돼 상한 왜곡이 없다. nDCG@5 0.911 |
| Full Recall | **0.956** | 정답을 놓치지 않았나 | top-5가 아니라 **반환 결과 전체** 기준. R@5(0.930)와의 격차가 '순위 밀림'의 크기다 |
| 기권 정확도 | **7/20** | 없는 걸 없다고 말하나 | 실패 13건 중 10건이 없는 직업명. 개념형과 원리적으로 구분 불가 — **약점으로 공개** |

**여기엔 천장 문제가 없다** — 유형별 P@R이 0.456~1.000으로 벌어져 강약을 말할 수 있다.

| 유형별 | R@5 | P@R | P@5 상한 |
|---|---|---|---|
| 전화 (n=30) | 1.000 | 1.000 | 0.21 |
| 회사명 (n=40) | 1.000 | 1.000 | 0.21 |
| 이름 (n=40) | 1.000 | 1.000 | 0.20 |
| 지역+직함 (n=40) | 1.000 | 0.850 | 0.21 |
| 개념형 easy (n=14) | 0.700 | 0.600 | 1.00 |
| **개념형 hard (n=19)** | 0.547 | **0.456** | 0.96 |

## 멀티턴 — 3개

`python scripts/eval_multiturn.py` · 시나리오 139 / 턴 386 / 22유형.
카드 데이터에서 생성하므로 데이터를 다시 만들면 같이 갱신된다.

| 지표 | 값 | 무엇을 재나 | 근거 |
|---|---|---|---|
| 체크리스트 (LLM 턴) | **0.990** | 답변에 필요한 값이 들어 있나 | **LLM이 실제로 생성한 턴만** 채점. 답변의 35%는 고정 문자열이라 섞으면 숫자가 부풀려진다 |
| 라우팅 · JGA · Hit@5 | **1.000 / 1.000 / 0.994** | **회귀가 없나** | 천장이라 '좋다'가 아니라 **'안 나빠졌다'**. 결함 6개를 고치는 동안 386턴이 안 깨졌다는 근거 |
| 커버리지 | **139 / 386 / 124** | 얼마나 넓게 봤나 | 시나리오 / 턴 / **서로 다른 발화 '틀'**. 분모만 보고하면 같은 시험을 이름만 바꿔 반복한 걸 숨기게 된다 |

진단용(헤드라인 아님): 슬롯 P/R/F1 · R@5 0.988 · MRR 0.994 · pass^k · 무관 요청 억제.
출력이 스스로 한계를 찍는다 — `라우팅 1.000 (361/361) <- 천장, 회귀 탐지용`.

## 고정 challenge set — 1개

`benchmark_final50_v3/` · 50시나리오 / 244턴 (외부 제작: `HJP-limited/ymj`)

| 지표 | 값 | 무엇을 재나 | 근거 |
|---|---|---|---|
| 값 정확도 | **47/50** | **실제로 좋아졌나** | 25/50에서 출발. 외부에서 만든 고정 셋이라 자기충족이 없다 — **멀티턴에서 유일하게 움직인 값** |

| 범주 | 전 | 후 |
|---|---|---|
| 장거리 재활성화 | 0/10 | **10/10** |
| 담화 순서 지시 | 0/10 | **10/10** |
| 빈 필드 기권 | 5/10 | **10/10** |
| 근접 상태 유지 | 7/10 | 9/10 |

우리 카드에서 만들어졌기에 정답 정의가 가능하다. 지문(SHA-256)·카드 실재를 직접 대조해
검증했다. **제작한 쪽에서는 실행되지 않았다** — 위 결함 발견·수정은 전부 이쪽 실행 결과다.

## 거부한 지표 — 4개

전부 **측정해 보고** 뺐다. "안 맞아서"가 아니라 "재 보니 이래서"다.

| 지표 | 제안 | 거부 이유 (측정값) |
|---|---|---|
| Exact Match | 외부 | 우리 답변 **40턴 전부 0.000**인데 값은 다 맞다. 라벨·쉼표 차이를 재는 지표다 |
| Answer F1 | 외부 | **0.267**. 같은 이유로 문장형 답변에 벌점 — 맞는 답이 0.29로 찍힌다 |
| Slot Accuracy | 외부 | JGA가 1.000이면 **논리적으로 1.000**. 슬롯 P/R/F1과 같은 사실의 중복 |
| 날것 Recall@5 | 외부 | 완벽한 검색기도 **상한 0.924**, 유형별로는 0.096까지 눌린다 |

**같은 잣대를 우리 지표에도 댔다** — 슬롯 P/R/F1과 체크리스트(결정적 턴)는 만점일 때
중복 보고라서 **실패했을 때만** 출력하도록 낮췄고, 무관 요청 억제(n=10)·pass^k(표본 18)에는
표본 수를 항상 같이 찍는다.
